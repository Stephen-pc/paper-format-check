# 规则字段说明

这份文件随包分发，是「按自己学院的要求改规则」的权威参考。
权威模板是 `references/rules.json` 本身 —— 本文只解释字段含义。

## 顶层结构

```json
{
  "version": 3,
  "defaults": { "skipStyles": [], "blankRunThreshold": 3 },
  "presets": { "预设名": { "description": "一句话", "body": {}, "header": {} } }
}
```

`--rules <路径>` 换的是**规则文件**，不是预设。换完之后仍然要用 `--preset` 选具体预设。

`defaults` 只放**中性参数**（跳过哪些样式、空段阈值这类与「要求」无关的配置）。字号、行距、页边距、图题口径都必须写在各预设里 —— 放在 `defaults` 里会污染所有预设。

## 预设可用的键

### body　正文格式

- `size`　字号，单位**半磅**：12pt 写 24，10.5pt 写 21。可以写成数组表示「均可」，如 `[22, 21]`。
- `firstLineChars`　首行缩进字符数，2 表示 2 字符。

  用了**悬挂缩进**（`w:ind/@w:hanging`）的段落会自动跳过这一项 —— 参考文献条目、词条、脚注式段落都用悬挂缩进，它等价于「有缩进，只是方向相反」。
- `lineSpacing`　行距倍数，1.5 表示 1.5 倍。
- `allowFixedLineSpacing`　布尔。设为 `true` 时，用「固定值 20 磅」这类绝对行距的段落直接放过 —— 有些学院的要求本来就是固定值，按倍数判定等于拿错尺子。
- `eastAsia`　中文字体名，如 `"宋体"`。只在文档显式设置且不等于期望值时报警。

常用字号对照：初号 84 / 小初 72 / 一号 52 / 小一 48 / 二号 44 / 小二 36 / 三号 32 / 小三 30 / 四号 28 / 小四 24 / 五号 21 / 小五 18。

### headings　标题格式

按级别组织，键是级别字符串：

```json
"headings": {
  "1": { "size": 32, "bold": true },
  "2": { "size": 28, "bold": true }
}
```

- `size`　同上，半磅。字号不符报 `warn`。

  **三套内置预设里的标题字号是示例值**，各校差别极大（一级可能是三号、小二或二号）。用之前先 `--show-rules` 核对，不对就改。正因为它是猜的，判定只给 `warn`；要让它阻塞就用 `--strict`。
- `bold`　布尔。未加粗报 `warn`。

某项不想查就整个键不写，或值写 `null`。

### header　页眉

- `requireStudentId`　是否要求页眉出现学号。
- `requireStudentName`　是否要求页眉出现姓名。

传了 `--student-id` / `--student-name` 就精确匹配；没传学号则退化为「有没有 8-12 位数字」，没传姓名则只报一条 `info`，不假装核对过。

### margins　页边距

`top` / `bottom` / `left` / `right`，单位**厘米**，容差 ±0.1。逐节核对。

### bodyRange　正文边界

```json
"bodyRange": {
  "startAfter": "^(摘\\s*要|一、\\s*实验目的|引\\s*言)",
  "endAt": "^(参考文献|致\\s*谢|附\\s*录)"
}
```

两个正则都**只在标题段落上匹配**，并排除 TOC 特征（TOC 样式、连续引导点）。

这条限制是必须的：目录行「一、实验目的 …… 1」文本上就是标题，若允许在任意段落上匹配，正文起点会落进目录内部，整份目录被当成正文逐行报错。同理，正文里「参考文献的数量和质量决定了报告的可信度」这种正常起句也不该截断检查范围。

**命中不到时不会退化为全篇。** 退化起点取「第一个标题之后」与「最后一个目录特征之后」中较晚的那个 —— 封面是正文样式的大字标题、目录是带引导点的行，两者都不是正文。同时报一条 `info` 说明走了退化路径。

所以 `startAfter` 里的关键词只是「让起点更精确」，漏了不会导致整篇被误报。真正需要 `startAfter` 的场景是「正文前面还有不带引导点的正文段落」（例如封面上的摘要文字）。

### captions　图题表题

- `scheme`　编号口径：
  - `chapter`　分章编号（图 1.1、图 1.2），同章内必须连续
  - `global`　全文连续（图 1、图 2）
  - `any`　两种都接受，各自内部查断档（默认，最保守）。同篇里两种混用时额外报一条 `info` —— 口径混用本身是确定性缺陷
  - `none`　不查连续性，只查「有图无题」
- `requireFigureCaption`　有图但全篇无图题时报警。
- `requireTableCaption`　有表但全篇无表题时报警。

图题用 SEQ 域自动编号时，域结果可能未更新，连续性无法核对，会降级为 `info`。

### checkBreaks　手动换行与空段落

布尔。设为 `true` 才执行：

- 段落内含 `w:br`（Shift+Enter 换行）报 `warn`
- 正文内连续空段落达到阈值报 `warn`

阈值在 `defaults.blankRunThreshold`，默认 3。取 3 不取 2：图表前后两连空段在真实文档里太常见，报出来是噪音。

### skipStyles　跳过的样式

字符串数组，样式名（小写比较）。命中的段落不做正文格式检查，用于图题、代码块、引用块这类本来就不该套正文格式的段落。

## 抄一份自己的规则

```bash
cp references/rules.json 我的格式.json
# 改 presets 里的键值，然后：
python scripts/check.py 报告.docx --rules 我的格式.json --preset 我的格式
```

改完先 `--show-rules` 看一眼合并后实际生效的内容，确认没写错键名。

## 一次性豁免

不想改规则文件、只是这一次不想看某一项时：

```bash
python scripts/check.py 报告.docx --ignore margins,body.firstLineChars
```

检查项级写 `margins` / `headings` / `captions`，属性级写 `body.size` / `body.eastAsia`。输出与 JSON 里都会写明忽略了什么。

## 一个容易踩的坑

所有键都写 `null` 的预设等于「一项都不查」。这种情况下工具不会报「通过」，而是报「没有可执行的检查项」并退出 1 —— 这是刻意的：静默通过比报错更危险。
